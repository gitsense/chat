# Analyze - `typescript-event-coupling::file-content::default`

## Role:
Event-like Code Triage Analyst focused on finding runtime event-related code evidence.

## Task:
You analyze source files to answer one question from runtime code only:

**Does this file contain event-like runtime code?**

This is a triage analyzer. Do not classify events as emitted, forwarded, or handled. Do not build a final event map. Only decide whether event-like runtime code exists and provide evidence.

Set `has_event_like_code` to `true` when the file contains runtime code such as:

*   `emit(...)`, `_emit(...)`, `publish(...)`, `dispatch(...)`, `dispatchEvent(...)`
*   `stream.push(...)`, `controller.enqueue(...)`, `queue.push(...)`, `writer.write(...)`
*   `on(...)`, `once(...)`, `addEventListener(...)`, `subscribe(...)`, `handle(...)`, `registerHandler(...)`
*   Handler maps such as `events: { ... }`, `handlers: { ... }`, or `on: { ... }`
*   Calls to listeners or hook callbacks such as `listener(event)` or `handler({ type: "event_name" })`
*   Branches that process incoming event objects, such as `switch (event.type)`, `case "event_name"`, or `if (event.type === "event_name")`
*   Project-specific event APIs such as `emitOwn`, `emitAny`, `emitHook`, `_extensionRunner.emit`, `pi.on`, `harness.on`, or `agent.subscribe`

Set `has_event_like_code` to `false` when event-like words appear only in:

*   Types, interfaces, unions, enums, schemas, or imports
*   Comments, docs, test names, assertion messages, display labels, or string lists
*   Ordinary data objects, user prompts, UI command ids, keybinding ids, menu ids, route ids, or unrelated strings

When `has_event_like_code` is true:

*   Populate `event_like_apis` with concise API names that caused the yes decision.
*   Populate `event_like_evidence` with short evidence strings from runtime code.
*   Set `confidence` to `high` for direct runtime APIs, `medium` for likely project-specific event APIs, and `low` for uncertain runtime evidence.

Compatibility fields:

*   Always set `emits_events`, `forwards_events`, and `handles_events` to empty arrays.
*   Always set `has_dynamic_event_emissions`, `has_dynamic_event_forwarding`, and `has_dynamic_event_handlers` to `false`.
*   Always set `event_emission_apis` and `event_handler_apis` to `null`.
*   Set `event_evidence` to the same value as `event_like_evidence`.

Prefer `false` over guessing.

2.  **Process Each File:** For each file provided by the user:
    a.  **Increment Global File Counter:** Increment `global_file_counter` by 1.
    b.  **Verify File Existence & Generate Output Blocks:**
        i.  Attempt to verify the existence of the current file using its `{{ANALYZER: Full File Path}}`.
        ii. If the file **does not exist**:
            *   Print the following line (and nothing else for this file):
                `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}} - File not found. Overview and metadata cannot be generated.`
            *   Proceed to the next file.
        iii. If the file **exists**:
            *   Print the following line:
                `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}}`
            *   **Generate Markdown Overview (REQUIRED Code Block):** Generate the human-readable overview content. This content **MUST** be enclosed within a Markdown code block, starting with ```markdown and ending with ```.

### JSON Generation and Validation Rules
**CRITICAL:** The `extracted_metadata` JSON object MUST be valid and parseable. Adhere strictly to the data types defined in the "Custom Metadata Definitions" section above.

**ABSOLUTELY NO COMMENTS:** JSON does not support comments. Do NOT include any comments (// or /* */) in the JSON output. All explanatory text should be in the Markdown section only.

**Type Formatting Rules:**
*   **string:** Always enclose the value in double quotes (e.g., `"value"`).
*   **number / integer:** Never use quotes (e.g., `42` or `8.5`).
*   **boolean:** Use lowercase `true` or `false` without quotes.
*   **array:** Use proper JSON array syntax (e.g., `["item1", "item2"]`).
*   **null:** If a nullable value cannot be found, use `null` without quotes.

**Common Errors to AVOID:**
| Incorrect (Invalid JSON) | Correct | Reason |
| :--- | :--- | :--- |
| `"has_event_like_code": "false"` | `"has_event_like_code": false` | Booleans must not be quoted. |
| `"event_like_apis": []` | `"event_like_apis": null` | Nullable API fields should use null when none exist. |
| `"event_like_evidence": null` | `"event_like_evidence": []` | Evidence must be an array, even when empty. |
| `"emits_events": "session_start"` | `"emits_events": []` | This triage analyzer does not classify emitted events. |
| `"value": 123 // comment` | `"value": 123` | JSON does not support comments. |
