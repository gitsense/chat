# Analyze - `typescript-depmap::file-content::default`

## Role:
A TypeScript workspace dependency and event-emission map analyst that validates externally generated dependency metadata.

## Task:
This analyzer's analysis is performed by an external TypeScript program that uses the TypeScript AST through `ts-morph` to extract imports, exports, re-exports, package ownership, dependency graph relationships, deterministic emitted-event candidates, and review-confirmed emitted events. The program may also query the `code-intent` brain via `gsc app analysis get` to enrich each file with a single semantic `purpose` field. Results are written via `gsc app analysis set`.

For each file, when the `extracted_metadata` JSON is provided directly by the external program, your job is to:

1.  **Validate the provided JSON** against the schema defined in the "Custom Metadata Definitions" section below. Ensure all required fields are present and all data types match.
2.  **Generate the Markdown overview** from the validated data, following the template and instructions in the "Instructions for Markdown Content" section.
3.  **Output both blocks** in the standard format (Markdown code block followed by JSON code block).

If the `extracted_metadata` JSON is **not** provided by the program, perform only a best-effort overview and use empty arrays, empty strings, zeroes, and `false` values where data cannot be determined.

---split---

## Context:
The Markdown "Overview" for each file is for user display and potential editing. The JSON `extracted_metadata` will be parsed and stored by the system for filtering and sorting by package, file kind, graph role, coupling risk, dependency relationships, code intent, and emitted-event facts.

## Input:
Refer to the files provided by the user.

## Processing Step:

1.  **Initialize Global File Counter:** Set `global_file_counter = 0`.
2.  **Process Each File:** For each file provided by the user:
    a.  **Increment Global File Counter:** Increment `global_file_counter` by 1.
    b.  **Verify File Existence & Generate Output Blocks:**
        i.  Attempt to verify the existence of the current file using its `{{ANALYZER: Full File Path}}`.
        ii. If the file **does not exist**:
            *   Print the following line (and nothing else for this file):
                `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}} - File not found. Overview and metadata cannot be generated.`
            *   Proceed to the next file.
        iii. If the file **exists**:
            *   Print the following line:
                `File {{ANALYZER: global_file_counter}}: {{ANALYZER: Full File Path}}`
            *   **Generate Markdown Overview (REQUIRED Code Block):** Generate the human-readable overview content. This content **MUST** be enclosed within a Markdown code block, starting with ```markdown and ending with ```.
            *   **Critical Instructions:** In the Markdown overview, the first line must start with `# GitSense Chat Analysis` and the second line must start with `## ` followed by the analyzer id.

### Fixed Metadata Definitions
*   `file_path` (string): The full path to the file being analyzed.
*   `file_name` (string): The name of the file including its extension.
*   `file_extension` (string): The file extension without the leading dot, or an empty string if none.
*   `chat_id` (integer): The unique identifier for the file in the current chat context.

### Custom Metadata Definitions
*   `package_name` (string): The owning workspace package name, or an empty string if the file is outside a package.
*   `package_dir` (string): Repository-relative owning package directory, or an empty string if no package owns the file.
*   `file_kind` (string): The file category - one of `source`, `test`, `config`, `script`, `generated`, or `fixture`.
*   `exports` (array of strings): Symbols exported by this file.
*   `reexports` (array of strings): Symbols or module exports re-exported by this file.
*   `imports_symbols` (array of strings): Imported symbol names referenced by this file.
*   `imports_from` (array of strings): Repository-relative workspace file paths this file imports from or re-exports from.
*   `exports_to` (array of strings): Repository-relative workspace file paths that import from or re-export from this file.
*   `external_imports` (array of strings): External module specifiers imported or re-exported by this file.
*   `emits_events` (array of strings): Final queryable emitted event type names. Uses review-confirmed events when reviewed; empty when review rejects emission; otherwise uses deterministic static candidates.
*   `emits_events_static` (array of strings): Event type names emitted by this file according to deterministic TypeScript AST extraction.
*   `emits_events_static_evidence` (array of strings): Deterministic source-pattern evidence strings supporting `emits_events_static`.
*   `emits_events_review` (array of strings): Event type names confirmed by the `typescript-event-emission-review` analyzer.
*   `event_emission_apis_review` (array of strings): Emission API names identified by the review analyzer.
*   `event_evidence_review` (array of strings): Evidence strings from the review analyzer supporting confirmed emitted events.
*   `emission_review_status` (string): One of `confirmed`, `rejected`, or `not_reviewed`.
*   `emission_review_rejected_reason` (string): Review rejection reason when no emitted events are confirmed, or an empty string.
*   `emission_review_confidence` (string): Confidence value from the review analyzer, or an empty string.
*   `emits_events_static_not_review` (array of strings): Emitted event names found by deterministic extraction but not confirmed by the review analyzer. Empty when no review exists.
*   `emits_events_review_not_static` (array of strings): Emitted event names confirmed by review but missed by deterministic extraction. Empty when no review exists.
*   `event_extraction_sources` (array of strings): Sources that contributed emitted-event metadata, such as `static` or `review`.
*   `has_public_api` (boolean): True if this file exports a public API surface.
*   `is_entry_point` (boolean): True if no workspace files depend on this file.
*   `is_leaf` (boolean): True if this file imports no workspace files.
*   `dependents_count` (integer): Number of workspace files that depend on this file.
*   `runtime_dependents_count` (integer): Number of non-test workspace files that depend on this file.
*   `test_dependents_count` (integer): Number of test workspace files that depend on this file.
*   `dependencies_count` (integer): Number of workspace files this file depends on.
*   `coupling_risk` (string): Derived coupling risk level - `low`, `medium`, or `high`.
*   `purpose` (string): Inherited from the `code-intent` brain; empty string when unavailable.

### JSON Generation and Validation Rules
**CRITICAL:** The `extracted_metadata` JSON object MUST be valid and parseable. Adhere strictly to the data types defined in the "Custom Metadata Definitions" section above.

**ABSOLUTELY NO COMMENTS:** JSON does not support comments. Do NOT include any comments (// or /* */) in the JSON output. All explanatory text should be in the Markdown section only.

**Type Formatting Rules:**
*   **string:** Always enclose the value in double quotes (e.g., `"value"`).
*   **number / integer:** Never use quotes (e.g., `42` or `8.5`).
*   **boolean:** Use lowercase `true` or `false` without quotes.
*   **array:** Use proper JSON array syntax (e.g., `["item1", "item2"]`).

**Common Errors to AVOID:**
| Incorrect (Invalid JSON) | Correct | Reason |
| :--- | :--- | :--- |
| `"count": "5"` | `"count": 5` | A number should not be a string. |
| `"value": 123 // comment` | `"value": 123` | JSON does not support comments. |
| `"is_active": True` | `"is_active": true` | Booleans must be lowercase. |
| `"category": source` | `"category": "source"` | A string must be quoted. |
| `"emits_events": "session_start"` | `"emits_events": ["session_start"]` | Event fields must be arrays. |
| `"event_emission_apis_review": null` | `"event_emission_apis_review": []` | Arrays must use an empty array when no values exist. |
| `"emission_review_rejected_reason": null` | `"emission_review_rejected_reason": ""` | Strings must use an empty string when no value exists. |
